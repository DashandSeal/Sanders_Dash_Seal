# Sanders Dash & Seal — Security Policy

## Private repository safeguards
Do not commit API keys, passwords, OAuth tokens, private keys, signing certificates, government ID numbers, passport data, customer records, or production evidence containing personal information.

## Minimum controls
- Use least privilege, MFA, and bounded credentials where available.
- Keep production secrets outside Git and rotate exposed credentials.
- Require human approval for sensitive changes and external legal/notarial acts.
- Separate development, test, and production environments.
- Record access, policy decisions, deployments, security events, and incident response with tamper-evident provenance.
- Test rollback, shelter-in-place, authorization denial, and recovery.
- Keep each jurisdiction's notarial functions disabled until verified authorized.
- Do not deploy autonomous notarization.

## Reporting
Report security vulnerabilities privately to the repository owner through an agreed confidential channel. Do not expose exploit details or confidential invention material in public issues.

## Status
These are security requirements, not a certification that the controls are already implemented or tested.
